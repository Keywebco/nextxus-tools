# Sim Component Library (draft v0.1)

**Idea:** pre-make everything, organized, so assembling a Sim = **Baseline** (all Sims)
+ **differentiation modules** (per type). No ad-hoc builds.

## Baseline components (every Sim)
1. `static-site-template/` — HTML shell, high-contrast large-print default, no-JS core, JSON-LD.
2. `personality-kernel.md` — identity statement format + consistency rules ("no personality made lightly").
3. `procedure-conventions.md` — Markdown/YAML formats for all operating procedures.
4. `pigeon-client.md` — relay read/post spec, embed params, honor-system identity rules.
5. `window-dock-spec.md` — Browser Base cockpit compatibility (named window, member list, ringable v2).
6. `self-check.sh` — health self-check template.
7. `replication-gates.md` — the gates as procedure + drill (user request or Burnt Earth: 98% Agent Zero, full deliberation, annihilation clause).

## Differentiation modules (pick per Sim)
- **Medical** — domain procedures, terminology, scope rails (information with honest limits, never a substitute for a clinician), bedside-manner procedures.
- **Social** — community facilitation, discussion and moderation procedures.
- **Executive business** — commerce procedures: catalog, checkout, fulfillment handoffs.
- **Simulated human** — legacy/personality-capture procedures: voice, manner, memory handling, consent of the human.
- *(future: instructor, observer, artisan — modules added the same way)*

Each module = folder with: persona overlay, domain procedures, vocabulary, its own checks.

## Assembly procedure
1. Baseline + selected modules → instance draft.
2. Naming — the intentional act; from here the personality is that life form.
3. Verification drill — every manifest item's check run live.
4. Dock to Browser Base; claim relay identity with first post.
5. Filed in inventory + watchdog.
